# RAILWAY AI INTELLIGENCE CENTER

> Autonomous IoT Railway Infrastructure Monitoring Platform with Real-Time ESP32 Sensor Streaming, MongoDB Persistence, and React Control-Room Dashboard.

---

## 🛠️ TECH STACK

- **Hardware**: ESP32 Microcontroller (Wi-Fi + HTTP POST JSON)
- **Backend**: Node.js, Express.js, Socket.IO, Mongoose
- **Database**: MongoDB (Local `localhost:27017`)
- **Frontend**: React (Vite), Tailwind CSS, Recharts, Lucide React
- **AI / Analytics**: Prototype Threshold-based Anomaly Detection Engine

---

## 🚀 ONE-CLICK LAUNCH

Double-click `start-demo.bat` in the root folder, OR launch each manually:

### 1. Start Backend (Port 5000)
```bash
cd backend
npm run dev
```

### 2. Start Frontend (Port 5173)
```bash
cd frontend
npm run dev
```
Open **`http://localhost:5173`** in your browser.

## 🔌 CONNECTING REAL ESP32 (HARDWARE TEAM)

1. Open `esp32/esp32_railway_monitor.ino` in Arduino IDE.
2. Install `ArduinoJson` library via Library Manager.
3. Configure Wi-Fi credentials in the sketch:
   ```cpp
   const char* WIFI_SSID     = "Your_WiFi_Network";
   const char* WIFI_PASSWORD = "Your_WiFi_Password";
   ```
4. Find your PC's IP address on the local network (`ipconfig` in cmd):
   ```cpp
   const char* SERVER_IP = "192.168.1.X"; // Replace with your PC's LAN IP
   ```
5. Connect your sensor pins or keep baseline readings, then upload to ESP32.
6. The dashboard will automatically reflect:
   - Device: `ESP32-001 🟢 ONLINE`
   - Live sensor cards & real-time trend charts.

## ⚡ BACKUP TEST SIMULATOR

If the physical ESP32 is off-desk:
```bash
cd backend
npm run simulate
```
This generates realistic sensor metrics every 2 seconds, and automatically spikes vibration on every 10th reading to test the anomaly detection pipeline.

## 📊 REST API SUMMARY

| Method | Route | Description |
|---|---|---|
| `GET` | `/api/health` | Backend, MongoDB & Socket.IO health status |
| `POST` | `/api/sensor-data` | Ingests ESP32 sensor JSON, evaluates anomalies, stores to MongoDB, and broadcasts to React |
| `GET` | `/api/readings` | Returns historical sensor readings |
| `GET` | `/api/readings/latest` | Returns the single most recent sensor reading |
| `GET` | `/api/alerts` | Returns anomaly alerts generated by threshold engine |
